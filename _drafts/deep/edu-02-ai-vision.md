## 이 단계가 다른 이유

앞 단계까지는 정답이 분명했다. 캐릭터가 목표에 닿으면 성공이고 안 닿으면 실패다. 이 단계부터는 다르다.

이미지 분류기를 만들려면 **무엇을 어떤 이름으로 부를지 아이가 정해야 한다.** 이 사진은 캔인가 페트병인가, 라벨이 뜯긴 페트병은 어느 쪽인가, 찌그러진 캔은. 정답이 데이터 안에 들어 있지 않고 아이의 머릿속에서 나온다.

이게 이 시리즈 전체에서 가장 중요한 경험이다. 도구가 결과를 만들어 주는 시대에 사람이 하는 일이 정확히 이것이기 때문이다.

> **모델을 만든다는 건 컴퓨터에게 규칙을 가르치는 일이 아니라, 내가 정한 기준을 예시로 보여 주는 일이다.**

## 도구 - Teachable Machine

구글이 제공하는 웹 도구다. 설치가 필요 없고, 브라우저에서 웹캠으로 사진을 모아 바로 학습시킨다. 학습된 모델은 웹페이지에 붙일 수 있는 형태로 내보낼 수 있다.

| 프로젝트 종류 | 입력 | 예시 |
|---|---|---|
| 이미지 | 웹캠 또는 업로드 사진 | 물건 분류, 손 모양 인식 |
| 오디오 | 마이크 | 소리 명령 인식 |
| 자세 | 웹캠 (신체 관절 추정) | 동작 구분 |

이 교재편은 이미지 프로젝트만 쓴다. 나머지는 같은 방식이므로 하나를 익히면 넘어갈 수 있다.

준비물은 인터넷 되는 컴퓨터와 웹캠, 그리고 분류할 물건 몇 개다.

## 다섯 회차 구성

| 회차 | 주제 | 하는 것 | 배우는 것 |
|---|---|---|---|
| 1 | 첫 분류기 | 물건 두 종류를 구분한다 | 예시를 모으면 구분이 된다 |
| 2 | 속이기 | 일부러 틀리게 만들어 본다 | 모델이 무엇을 보고 있는지 |
| 3 | 기준 정하기 | 애매한 경우를 종이에 정의한다 | 정답은 내가 정한다 |
| 4 | 시험 보기 | 학습에 안 쓴 사진으로 채점한다 | 학습 데이터로 채점하면 안 된다 |
| 5 | 웹페이지에 붙이기 | 결과에 따라 화면이 바뀌게 한다 | 모델을 프로그램의 부품으로 쓴다 |

## 1회차 - 첫 분류기

물건 두 종류를 고른다. 처음에는 확실히 다른 것이 좋다. 예를 들어 종이컵과 숟가락.

1. Teachable Machine에서 이미지 프로젝트를 연다
2. Class 1의 이름을 "종이컵"으로 바꾸고 웹캠으로 사진을 모은다
3. Class 2의 이름을 "숟가락"으로 바꾸고 같은 방식으로 모은다
4. 학습 버튼을 누른다
5. 카메라 앞에 물건을 들고 결과를 확인한다

여기서 대개 아이가 놀란다. 몇십 장 모았을 뿐인데 구분이 된다.

**어른의 질문**:
- "사진을 몇 장씩 모아야 될까? 10장으로 해 보고, 50장으로 해 보고 차이를 보자"
- "한 각도로만 찍으면 어떻게 될까?"

## 2회차 - 속이기

이 회차가 이 교재의 핵심이다. 잘 되는 걸 확인하는 게 아니라 **일부러 틀리게 만든다.**

시도해 볼 것들:

- 물건은 그대로 두고 배경만 바꿔 본다
- 손으로 반쯤 가려 본다
- 조명을 어둡게 해 본다
- 두 물건을 같이 들어 본다
- 아무것도 안 들고 카메라를 본다

마지막 항목에서 재미있는 일이 벌어진다. 아무것도 없는데도 모델은 반드시 둘 중 하나를 고른다. "모르겠다"는 선택지를 안 줬기 때문이다.

여기서 나오는 대화가 이 회차의 목적이다.

**어른의 질문**:
- "아무것도 없는데 왜 종이컵이라고 할까?"
- "'모르겠음'이라는 종류를 하나 더 만들면 어떻게 될까?"

실제로 "아무것도 없음" 클래스를 추가하고 빈 배경 사진을 모아 다시 학습시켜 본다. 결과가 달라지는 걸 직접 본다.

배경 문제도 좋은 실험이다. 종이컵은 항상 책상에서, 숟가락은 항상 손에 들고 찍었다면 모델은 물건이 아니라 배경을 배웠을 수 있다. 종이컵을 손에 들어 보면 드러난다. 이걸 확인하는 순간이 아이가 "모델이 내 의도가 아니라 사진에 있는 걸 배운다"는 걸 이해하는 지점이다.

## 3회차 - 기준 정하기

이제 애매한 것으로 넘어간다. 예를 들어 재활용 분류를 한다고 하자.

종이에 표를 그리고 아이가 채운다.

| 무엇을 | 어느 쪽으로 | 왜 |
|---|---|---|
| 깨끗한 페트병 | 페트 | |
| 라벨 붙은 페트병 | ? | |
| 안에 음료가 남은 병 | ? | |
| 찌그러진 캔 | ? | |
| 종이컵 | ? | |

물음표를 아이가 채운다. 정답은 없다. 중요한 건 **결정하고 적는 것**이다.

그 다음 그 기준대로 사진을 모은다. 라벨 붙은 페트병을 페트로 정했으면 그런 사진을 페트 클래스에 넣는다. 여기서 아이는 자기가 적은 기준과 자기가 모으는 데이터가 일치하는지 스스로 확인하게 된다.

이게 실무의 라벨링 지침서와 똑같은 구조다. 어른이 하는 데이터 프로젝트에서도 가장 어려운 부분이 여기다.

## 4회차 - 시험 보기

아이가 만든 모델을 채점한다. 규칙은 하나다.

**학습에 쓴 사진으로 채점하지 않는다.**

방법은 간단하다. 사진을 모을 때부터 일부를 따로 빼 둔다. 예를 들어 클래스마다 40장을 모았으면 30장으로 학습하고 10장은 시험용으로 남긴다. 학습이 끝나면 남긴 10장을 하나씩 보여 주고 맞았는지 표시한다.

표를 그려서 센다.

| | 맞음 | 틀림 |
|---|---|---|
| 페트 (10장) | | |
| 캔 (10장) | | |
| 종이 (10장) | | |

여기서 두 가지를 발견한다.

- 학습할 때 화면에 뜨던 정확도보다 낮게 나온다. 왜 그런지 이야기한다
- 특정 종류만 유독 많이 틀린다. 그 종류의 사진을 더 모으면 나아지는지 확인한다

두 번째가 좋은 실험이다. 데이터를 늘려서 문제를 고치는 경험은 이 나이에 하기 좋다.

## 5회차 - 웹페이지에 붙이기

Teachable Machine에서 모델 내보내기를 누르면 웹에서 쓸 수 있는 주소와 코드 조각이 나온다. 이걸 붙여 넣으면 아이가 만든 모델이 웹페이지에서 돈다.

```html
<!-- 라이브러리 두 개를 불러온다 -->
<script src="https://cdn.jsdelivr.net/npm/@tensorflow/tfjs@latest/dist/tf.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/@teachablemachine/image@latest/dist/teachablemachine-image.min.js"></script>

<script>
// Teachable Machine이 알려 준 내 모델 주소
const URL = "여기에_내보내기에서_받은_주소";
let model, webcam;

async function init() {
  model = await tmImage.load(URL + "model.json", URL + "metadata.json");
  webcam = new tmImage.Webcam(300, 300, true); // 가로, 세로, 좌우반전
  await webcam.setup();
  await webcam.play();
  document.getElementById("cam").appendChild(webcam.canvas);
  window.requestAnimationFrame(loop);
}

async function loop() {
  webcam.update();                       // 카메라 화면 갱신
  const result = await model.predict(webcam.canvas);  // 예측
  // result는 [{className: "페트", probability: 0.93}, ...] 형태
  const top = result.sort((a, b) => b.probability - a.probability)[0];
  document.getElementById("answer").innerText = top.className;
  window.requestAnimationFrame(loop);
}
</script>
```

여기서 아이가 할 일은 코드를 이해하는 게 아니라 **결과를 가지고 무엇을 할지 정하는 것**이다.

- 페트로 판정되면 화면을 파란색으로 바꾼다
- 캔이면 소리를 낸다
- 확률이 낮으면 "잘 모르겠어요"라고 띄운다

마지막 항목이 특히 좋다. 2회차에서 겪은 "모르겠다는 선택지가 없다"는 문제를 코드로 해결하는 것이다. 확률이 0.7 미만이면 판정하지 않는다는 규칙을 아이가 정하고, 그 숫자를 바꿔 가며 결과를 본다.

이 부분의 코드는 어른이 Claude 같은 도구에게 만들게 해도 된다. **아이가 정하는 건 규칙이고, 코드는 도구가 쓴다.** 이 구조 자체를 아이가 보는 것도 배움이다.

## 확장 - 화면 밖으로

여기까지 하면 다음 단계가 자연스럽게 나온다. 화면 색이 바뀌는 대신 실제로 뚜껑이 열리거나 LED가 켜지면 좋겠다는 생각이 든다. 그게 아두이노편이다.

## 이 단계를 마쳤다고 볼 기준

- 모델이 틀렸을 때 "데이터를 더 모아야겠다" 또는 "기준이 애매했다"로 원인을 찾는다
- 학습에 쓴 사진으로 채점하면 안 된다는 걸 설명할 수 있다
- 자기가 정한 분류 기준을 말로 설명할 수 있다

> **아이가 배우는 건 인공지능이 똑똑하다는 사실이 아니라, 인공지능이 자기가 보여 준 것만 배운다는 사실이다.**

이 감각이 있으면 나중에 어떤 도구를 만나도 "이 도구는 무엇을 보고 이런 답을 냈을까"를 묻게 된다. 그게 검증의 시작이다.
